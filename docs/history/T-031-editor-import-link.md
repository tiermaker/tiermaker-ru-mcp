# T-031: импорт доски в редактор по ссылке и из файла (для MCP v1)

## Цель
Внешний клиент (будущий `tiermaker-mcp`) собирает тир-лист у себя и даёт пользователю ссылку
`/create#tm=<payload>`; редактор открывает её как гостевой черновик. Плюс тот же формат через «Импорт из файла».
Сервер, API и права не меняются.

## Контекст
- План: `.team/tasks/mcp-v1-plan.md`; разведка `.team/tasks/T-030-mcp-recon.notes.md` (п.1, 5, 6).
- Редактор и черновик: `frontend/components/tier-list-maker.tsx` (~1566, 1666), `frontend/lib/tier-list-editor-session.ts:146-153`, `frontend/app/create/**`.
- Формат доски: `backend/api/tier_list_v2.py:445-534,684-764` (rows/allItems/placements), лимиты `backend/api/tier_lists/save_request.py:10-67`.
- Картинки: `frontend/app/api/image-proxy`, `frontend/lib/image-proxy-security.ts`, CSP `frontend/next.config.mjs:34`.

## Что сделать
1. Модуль `frontend/lib/tierlist-import.ts`: тип и валидатор `TierListImport v1`
   `{version:1, title, templateSlug?, tiers:[{id,label,color}], items:[{id,label?,imageUrl?}], placements:{[tierId]:itemId[]}}`;
   кодирование/декодирование `base64url(deflate(JSON))` (без новых тяжёлых зависимостей; можно CompressionStream с fallback).
   Лимиты: ≤ 20 тиров, ≤ 200 элементов, label ≤ лимитов сайта, imageUrl — только `https?:` (и `data:image/*` не принимать), payload ≤ 32 КБ после сжатия.
   Неизвестные/битые поля → понятная ошибка, а не падение. Не размещённые элементы → пул; дубли id → ошибка.
2. Маппинг в внутреннее состояние редактора (то же, что даёт сохранённый черновик/шаблон). `templateSlug` — если шаблон существует и опубликован, привязать как при создании из шаблона; иначе игнорировать с предупреждением.
3. `/create#tm=…`: при загрузке прочитать фрагмент, провалидировать, открыть как гостевой черновик; после импорта убрать фрагмент из адреса (`history.replaceState`). Если уже есть несохранённый черновик — спросить, заменить ли его. Без автосохранения на сервер.
4. Внешние картинки показывать через `/api/image-proxy` (CSP не расширять). При сохранении после входа — существующий путь сервера (он сам скачивает URL).
5. «Импорт из файла» (`.tierlist.json`, та же схема) — кнопка в меню редактора рядом с экспортом. Если уже есть «экспорт JSON» — сделать формат совместимым; если нет — добавить «Экспорт в .tierlist.json» в той же схеме (round-trip).
6. Ошибки импорта — короткое сообщение пользователю (toast), без технических деталей.
7. Документация схемы: `frontend/lib/tierlist-import.md` (будет скопирована в OSS-репо MCP): поля, лимиты, пример, пример ссылки.
8. `CHANGELOG.md`; новость в `frontend/lib/blog.ts` — коротко, общими словами («доску теперь можно открыть по ссылке или из файла»), по правилам notes.

## Не делать
- Не менять backend, API, права, CSP, лимиты сервера. Не трогать прод.

## Критерии приёмки
- Unit-тесты модуля: валидная доска round-trip encode→decode; каждый лимит; битый base64/JSON; дубли id; `javascript:`/`data:` URL отклонены; не размещённые → пул.
- E2E (Chromium): открыть `/create#tm=<фикстура>` → тиры с нужными именами/цветами/порядком, элементы на местах, фрагмент убран из URL; импорт файла даёт то же; экспорт→импорт round-trip; битая ссылка → сообщение, редактор работает.
- Картинка из фикстуры показывается через image-proxy (в dev — локальный/разрешённый URL).
- `pnpm lint`, typecheck, `BACKEND_PYTEST_ADDOPTS=--nomigrations SEED_TEST_REFERENCE_DATA=true make test-predeploy` зелёные.
