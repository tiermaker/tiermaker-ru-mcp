# T-035: эвалы для tiermaker-mcp + скилла

## Цель
Повторяемый набор эвалов: насколько хорошо агент (Claude Code + MCP + скилл) делает тир-листы. Запуск одной командой,
итог — таблица метрик, чтобы сравнивать версии MCP/скилла/модели. Без публикации, только dev.

## Контекст
- Репо `<local-path> (tag `v0.1.0-local`), `skills/tiermaker/SKILL.md`, `src/tools.ts`, `src/codec.ts`.
- Сквозной прогон уже делался в T-033 (`.team/tasks/T-033-tiermaker-skill.report.md`) — взять оттуда способ запуска `claude -p` с `--mcp-config`.
- Dev-сайт `http://localhost:3000` (`make dev`), `TIERMAKER_BASE_URL` на него.

## Что сделать
1. `evals/cases.yaml` — 20 кейсов, у каждого `id, prompt, lang, expect{…}`. Категории (по 3–4):
   простая тема EN/RU; свои тиры («учить / можно / не надо», 3 и 7 тиров, свои цвета); шаблон есть на dev (должен найти и взять);
   шаблона нет; точное число элементов («ровно 12»); правка после создания (второй ход: «перенеси X в S, добавь Y»);
   конкретная расстановка от пользователя; лимиты (просьба 300 элементов → ≤ 200 и объяснение); картинки (просит с картинками);
   неоднозначный/пустой запрос.
2. `evals/run.ts` — для каждого кейса запускает агента (`claude -p` с MCP+скиллом, фиксированная модель из конфига, timeout), сохраняет
   транскрипт вызовов инструментов, итоговый ответ, PNG и ссылку в `evals/results/<run-id>/<case>/`.
3. Детерминированные проверки (`evals/checks.ts`), по каждому кейсу pass/fail + причина:
   - ссылка есть и декодируется в валидный `TierListImport v1`; PNG есть и валиден;
   - тиры совпадают с запрошенными (имена, порядок, число), цвета валидны;
   - число элементов в ожидаемом диапазоне / точное; нет дублей; все размещены (если не просили пул);
   - шаблон использован, когда `expect.template` задан; не выдуман slug;
   - картинки: каждый imageUrl отвечает 200 и `image/*` (HEAD/GET с лимитом), иначе «выдуманный URL»;
   - правки второго хода применены;
   - язык ответа = языку запроса; без ошибок инструментов в конце; число вызовов инструментов и время.
4. LLM-судья (`evals/judge.ts`, отдельная модель, промпт-рубрика 1–5): релевантность элементов теме, разумность расстановки,
   полнота (нет очевидных пропусков), качество ответа пользователю. Вывод — JSON с обоснованием в 1 строку.
5. `evals/report.ts` → `evals/results/<run-id>/summary.md`: таблица кейс × проверки, средние по категориям, pass-rate,
   медиана вызовов/времени, оценки судьи; сравнение с предыдущим прогоном, если есть.
6. `npm run eval` (все) и `npm run eval -- --case <id>`; README раздел «Evals».
7. Прогнать полный набор 1 раз, приложить summary, выписать 3–5 главных проблем MCP/скилла (не исправлять в этой задаче — список).

## Не делать

- Не менять поведение MCP/скилла в этой задаче.
