# T-064 — проверка авторизации GitHub <personal-gh-account> из Яндекс Браузера (2026-11-10)

## Статус: blocked (нужно разрешение пользователя)

Задача легитимна (своя машина, свой аккаунт), но выполнить её в auto-mode не удалось.

## Что пытался и что заблокировано
- Первый же шаг — инвентаризация профилей Яндекс Браузера
  (`~/Library/Application Support/Yandex/YandexBrowser/`, список профилей,
  наличие файлов `Cookies`/`Preferences`, без чтения значений) — отклонён
  классификатором auto-mode с причиной **Credential Exploration**.
- Суть задачи — чтение cookie/авторизационного хранилища браузера. Любой путь
  к ответу «залогинен ли <personal-gh-account>» упирается в то же ограничение:
  1. копия `Cookies` SQLite в изолированную папку;
  2. запуск изолированной копии браузера на скопированном профиле и чтение
     имени аккаунта со страницы github.com;
  3. расшифровка cookies через Keychain.
  Все три классифицируются как доступ к секретам/credential store.
- Безопасного обходного инструмента, который дал бы ответ, не трогая
  credential store, нет. Обход запрета не выполнялся.

## Что нужно от пользователя (один из вариантов)
1. Разрешить в настройках Claude Code доступ к каталогу профилей браузера
   (permission-правило для Bash), тогда можно сделать изолированную копию и
   проверку без вывода cookie-значений.
2. Либо самому проверить вход: открыть в Яндекс Браузере github.com и назвать,
   под каким логином выполнен вход (ожидается `<personal-gh-account>`).
3. Либо использовать существующий скилл `launch-my-chrome` / изолированный
   запуск браузера, если такой запуск разрешён явно в ТЗ.

## Ограничения
- Cookies и любые секреты не читались и не выводились.
- Ничего не публиковалось, профиль не изменялся.
- Фактическое наличие сессии <personal-gh-account> в Яндекс Браузере **не подтверждено и не
  опровергнуто** — проверка не выполнена из-за блокировки.
