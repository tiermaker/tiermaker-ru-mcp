# T-030 — MCP reconnaissance

1. Гость редактирует только в браузере: rescue-черновик в `localStorage`, без серверной доски (`frontend/components/tier-list-maker.tsx:1566,1666`; `frontend/lib/tier-list-editor-session.ts:146-153`); PNG экспортируется клиентским canvas без save (`frontend/tests/e2e/editor-reliability.spec.ts:147-169`). Save/share требуют token до запроса (`frontend/components/tier-list-maker.tsx:1858-1861,2058-2128`), поэтому ни редактировать серверную доску, ни «забрать» её в аккаунт гость не может.
2. Браузерские запросы досок идут через Next `/api/user-tier-lists/*` в Django (`frontend/app/api/user-tier-lists/route.ts:6-21`, `[uuid]/route.ts:6-23`); proxy выдаёт HttpOnly `tm_anonymous` (24 ч.) и HMAC-заголовок только для throttle (`frontend/lib/proxy-anonymous-identity.ts:3-9,56-76`, `frontend/app/api/_proxy.ts:222-237`). Внешний Node может читать Django напрямую, но не воспроизвести подпись и не получит guest-write API.
3. Поиск/категории доступны гостю: `GET /api/templates/catalog/?q=&category=&tag=&sort=&page=` и `GET /api/templates/` (public, summary; `backend/api/template_views.py:144-204,206-284`), `GET /api/categories/`, `GET /api/categories/{slug}/` (`backend/api/urls.py:120-121`, `template_public_views.py:24-55`); `GET /api/templates/{id}/` или `/api/templates/by-slug/{slug}/` возвращает опубликованный public/unlisted шаблон с `items` (`backend/api/template_views.py:302-347`, `template_public_views.py:150-191`, `serializers.py:637-747`).
4. Единственный create: `POST /api/user-tier-lists/`, обязательный `tier_data`, опциональны `title`, numeric `template`/`tier_data.templateId`, `visibility`, `parent_tier_list_uuid`, `Idempotency-Key`/`save_operation_id`; PATCH того же UUID заменяет структуру/элементы и visibility (`backend/api/tier_lists/views.py:250-271,549-643,953-961`; `tier_lists/save_request.py:77-122`). Оба метода `IsAuthenticated`, owner-only (`views.py:250-253,343-350,979-997`): для гостя сейчас 401, так что создание «из шаблона» и «с нуля» одинаково недоступны.
5. `tier_data`: `rows:[{id,label,color}]` задаёт порядок/названия/цвет, `selectedTierIds` скрывает строки; `allItems` содержит карточки, `tiers/placements` — `itemIds` по порядку, отсутствующие placement — pool (`backend/api/tier_list_v2.py:445-534,684-764`; `models.py:1111-1155`). Границы: 500 items, при рендере 100 rows/500 placements (`tier_lists/save_request.py:10-13,36-67`); serializer дополнительно 5 MiB JSON, 20 rows и base64 images до 2 MiB/20 MiB total (`serializers.py:547-619`), proxy 12 MiB/Django 10 MiB (`frontend/app/api/_proxy.ts:15-17,148-181`; `backend/tiermaker/settings.py:349-352`).
6. Custom `imageUrl` уже допускает `data:image` и внешний http(s) URL: сервер скачивает URL (8 c, 5 MiB), проверяет scheme/DNS/public-IP/allowlist/redirect/content-type, валидирует 2 MiB JPEG/PNG/WebP/HEIC, оптимизирует в WebP и кладёт preview+working в S3 (`tier_list_v2.py:393-442`; `http_safety.py:35-114`; `storage_utils.py:35-70,133-206`). Но это выполняется лишь внутри authenticated save; отдельного guest upload/from-URL endpoint нет.
7. Защита: write API всё равно блокирует auth/access plan (`backend/api/tier_lists/views.py:250-266,559-569`; `access.py:380-445`); anon throttle ключ — проверенный proxy-id, иначе client IP, default 100/hour, create 5/min, export 10/min (`throttles.py:20-53,93-116`; `settings.py:371-381`). Captcha есть для report/comments, не для save (`tier_lists/views.py:2258-2267`; `template_views.py:1063-1071`); middleware может FULL/READ_ONLY блокировать по IP/fingerprint (`middleware.py:361-452`). Подписанный check/SSR header — только внутренний bypass, не клиентский credential (`throttles.py:56-75`).
8. Ссылка публична только после authenticated unlisted/public: retrieve разрешает unlisted draft/published или public published (`tier_lists/queries.py:317-343`), `share_url` — `/tierlist/{uuid}` (`serializers.py:313-318`); public catalogue — лишь public+published, а SEO требует отдельного moderation approval (`queries.py:44-52`; `frontend/lib/seo.ts:67-70`). Гость не может попасть в каталог/публикацию; public publication требует rules, verified email, items/validation (`tier_lists/views.py:738-852`), moderator может block sharing.
9. Серверный persisted export `GET /api/user-tier-lists/{uuid}/download-image/` отдаёт JPEG, но требует full authenticated access (`tier_lists/views.py:2445-2487`); guest-only `POST /download-only/` также проходит `require_full_access` и отдаёт JPEG (`views.py:2544-2595`). Public OG JPEG существует для published public/unlisted (`views.py:2489-2507`), но API PNG export нет; UI PNG — client-side.
10. CORS в prod allowlist-only, с credentials; session POST подпадает под CSRF, хотя Node direct HTTP не нуждается в CORS/CSRF и всё равно не может пройти auth-write (`backend/tiermaker/settings.py:322-341,354-369`). Next proxy отбрасывает Origin/cookie, преобразуя авторизацию в Token (`frontend/app/api/_proxy.ts:88-145`), поэтому MCP не должен рассчитывать на browser session.
11. Пробелы v1 MCP: **L** guest-owned create/PATCH/read capability (нужны opaque write token, TTL/claim-to-account и owner check); **M** явный MCP contract/tools вместо browser-shaped `tier_data` plus stable validation/error schema; **M** first-class `image_url` ingestion endpoint/limits allowlist policy; **M** guest share URL with abuse quota/moderation; **M** server PNG export or documented client renderer; **S** CORS не нужен Node MCP, но нужны API key/auth, rate-limit identity и observability.
